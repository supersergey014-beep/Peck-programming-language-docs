01

THE ENGINE

Introduction & architecture

Hypha source files use the .hy extension. The Hydra Compiler Engine tokenizes and parses a source program, validates its declarations, lowers it to LLVM IR, and emits a native object file. The hy command can then link that object into an executable with clang++.

The current implementation is a small, evolving language engine rather than a full production compiler. This handbook marks behavior that is metadata-only or intentionally limited, so examples match what the compiler can currently execute.

↳

Quick start

A Hypha program declares an entry function with Str main(). Blocks close with End, and the native entry point returns a zero exit code when it reaches the end.

hello.hy
Str main() {
    Output.string("Hello, Hypha!")
    End
}
↳

Build the engine

Build from the repository root. CMake locates the LLVM development package; executable linking requires clang++ on PATH.

shell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
build/hy examples/hello.hy -o hello
./hello

Use -c to emit an object file without linking: build/hy examples/hello.hy -c -o hello.o. If LLVM is installed outside the default search paths, pass -DLLVM_DIR=/path/to/lib/cmake/llvm to CMake.

i

Implementation note The compiler targets the host architecture through LLVM's native target. Some syntax is currently compile-time metadata only; each section calls this out explicitly.

02

VALUES & STORAGE

Variables & mutability

Declarations begin with a type word or mutability modifier. A suffix after ! selects a storage type; var infers it from the initializer. Initializers are required.

SuffixHypha typeLLVM typeExample
!NIntegeri32var age!N = 16
!FFloatfloatvar ratio!F = 0.5
!DDoubledoublevar precise!D = 3.14
!BBytei8bt flags!B = 1
!CCharacteri8char mark!C = 'P'
!L, !strStringptrline label!L = "text"

data stores a raw byte buffer, for example data buffer!D = "raw bytes"; array declares a homogeneous array literal. var items = {2, 4, 6} infers an array, while array items = {2, 4, 6} states it explicitly.

mutability.hy
change score!N = 10
score = score + 1

const ceiling!N = 99
mut fixed!N = 4
mut-t temporary[tk-200] = 1
change · chn

Mutable binding. alwchang and alwchn are mutable aliases.

mut · const

Immutable binding. Reassignment is rejected by the compiler.

mut-t · mut-time

Stores a tk-N duration in the AST; timed freezing is not enforced at runtime yet.

Without a mutability modifier, a declaration follows the engine's mutable default. Struct fields use the same suffixes and modifiers.

03

BRANCHES & REPETITION

Control flow

Conditions compare scalar values with ==, !=, <, >, <=, or >=. Parentheses around an if condition are optional. Branch blocks end at }; an inner End is optional.

branches.hy
if age >= 18 {
    Output.string("Adult")
} else if (age == 16) {
    Output.string("Teenager")
} else {
    Output.string("Child")
}

Exit-tested loops

while executes its body first, then evaluates the cond-end condition. A true condition branches back to the body. Consequently, even a false condition runs the body once.

counter.hy
change counter!N = 0
while {
    counter = counter + 1
    cond-end = (counter < 5)
}

cond-end = (true) creates an infinite loop. The optional tuple form (true, speed) accepts an integer from 0 to 50. The speed value is parsed as metadata only; it does not throttle execution.

A bounded for loop declares a counter before the body and increments it after each pass:

bounded.hy
for var i!N = 0 {
    Output.string("pass")
    cond-end = (3)
}
04

COMPOSITION

Functions

Declare functions with Str or its alias func. Parameter types are written as suffixes; the optional suffix after ) is the return type. Omitting it declares a void function.

functions.hy
Str add(var a!N, var b!N) !N {
    ret a + b
    End
}

func update_score(change current!N, var bonus!N) !N {
    current = current + bonus
    ret current
    End
}

change total!N = add(score, bonus)

Parameters marked var, mut, or const are immutable within the function. change/chn and alwchang/alwchn permit reassignment. Calls can be used as initializer expressions or as standalone statements.

05

LAYOUT & OWNERSHIP

Memory & pointers

struct declares a named LLVM struct layout. Fields use Hypha suffixes and can be read or assigned through pointer member access. select(TypeName) allocates storage with malloc; release that allocation with free.

pointers.hy
struct Point {
    change x!N
    change y!N
    End
}

change value!N = 42
var pointer = &value
*pointer = 100

var point = select(Point)
point.x = value
free(point)
&xaddress of*pdereference^pdereference alias@xaddress aliasp.fieldfield GEP
!

Ownership is manual. Pointers created by select() must be freed exactly once. The current implementation supports scalar pointees and struct pointers; pointer arithmetic and general nested pointer expressions are not yet implemented.

Source imports

pack and import are equivalent directives. Each quoted path is resolved relative to the importing file; imported declarations can define structs, enums, and functions. The parser canonicalizes paths to avoid importing a file more than once, including through cycles.

main.hy
pack "types.hy"
      import "helpers.hy"

      Str main() {
          End
      }
06

TAGS & BRANCHING

Enums & pattern matching

numer declares an enum whose variants map to integer tags in declaration order, starting at zero. respon reads the enum value and lowers matching arms to an LLVM switch. Each pattern names both the enum and its variant.

status.hy
numer Status {
    Active,
    Disabled
    End
}

var state = Status.Active
respon state {
    Status.Active {
        Output.string("Status is active")
    }
    Status.Disabled {
        Output.string("Status is disabled")
    }
    End
}

Unknown enum names, missing variants, duplicate cases, and a pattern whose enum does not match the subject produce compilation errors. Unlisted tags take the switch default and continue after the respon block.

BEHAVIOR MODIFIERS

Meta-methods & custom behavior

Meta-method calls use ordinary call syntax, including dotted names. The built-in modifier vocabulary includes these families:

Updateupdate()update.fn()update.str()update.other()
Editedit()edit.fn()edit.str()edit.other()not.edit()ret.edit()
Flowoff()on()next()off.next()not.requir()negative()positive()
Inputinput()input.off()line()
meta.hy
change-method lock_var {
    off(edit)
    End
}

var count!N = 1
lock_var()

change-method registers a named compile-time sequence of recognized modifiers. Modifier calls are currently no-op annotations: they are parsed and validated but do not change runtime state or rewrite variables. A custom method expands to those annotations and accepts no parameters.

08

BOUNDARIES & FAILURES

Input & diagnostics

input() and line() read one line from standard input and return a string pointer. The reader consumes through newline or EOF and caps each line at 4095 bytes. input.off() is a recognized meta annotation; it is not an input read.

stdin.hy
var first = input()
var second = line()
Output.string("Read two lines")

A source-level panic("reason") prints the diagnostic to standard output and terminates the process with abort(). Front-end and code-generation errors are reported by hy with a source location where available and a concise reason; compilation exits unsuccessfully rather than emitting an executable.

failure.hy
if missing_value == 0 {
    panic("value is unavailable")
}
